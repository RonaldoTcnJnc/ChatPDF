CÓMO FUNCIONA EL RAG
====================

1. El usuario escribe una pregunta
2. Se convierte a un "embedding" (número vector)
3. Se busca en ChromaDB documentos similares
4. Se recuperan los fragmentos más relevantes
5. Se envían al modelo Llama 3 como contexto
6. El modelo genera una respuesta basada en el contexto
7. Se muestra la respuesta mejorada y precisa

VENTAJAS:
  ✓ Respuestas basadas en tus documentos
  ✓ Funciona 100% local (sin API externa)
  ✓ Datos privados (en tu PC)
  ✓ Bajo costo computacional
  ✓ Preciso y contextualizado


PERSONALIZACION
===============

Edita config.json para cambiar:

1. Servidor LMStudio:
   "base_url": "http://localhost:1234/v1"

2. Modelo de embeddings:
   "embeddings_model": "all-MiniLM-L6-v2"
   Opciones: all-mpnet-base-v2, multilingual-e5-base

3. Tamaño de chunks:
   "chunk_size": 500
   (Aumentar para papers largos)

4. Contexto recuperado:
   "retrieval_k": 3
   (Cuántos documentos usar de referencia)

5. Creatividad del modelo:
   "temperature": 0.7
   (0=preciso, 1=creativo)


PREGUNTAS FRECUENTES
====================

P: ¿Dónde coloco los PDFs?
R: En la carpeta ./pdfs/ (se crea automáticamente si no existe)

P: ¿Necesito internet?
R: Solo para descargar los modelos (primera vez)
   Luego todo funciona offline completamente

P: ¿Cuánta memoria necesito?
R: ~2GB para Llama 3 + ~200MB para embeddings
   ChromaDB usa ~50MB por 1000 chunks

P: ¿Cómo mejoro la precisión?
R: - Usa "all-mpnet-base-v2" en lugar de "all-MiniLM-L6-v2"
   - Aumenta retrieval_k a 5 o más
   - Proporciona PDFs de mejor calidad

P: ¿El sistema es privado?
R: Sí, todo corre localmente en tu PC. Sin enviar datos a la nube.

P: ¿Funciona offline completamente?
R: Sí, después de descargar los modelos de embeddings la primera vez

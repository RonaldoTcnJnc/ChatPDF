💡 COMO FUNCIONA
================================================================================

RAG = Retrieval-Augmented Generation

[Tu pregunta]
     ↓
[Se convierte a vector numérico]
     ↓
[ChromaDB busca documentos similares en los PDFs]
     ↓
[Recupera los 3 fragmentos más relevantes]
     ↓
[Envía contexto + pregunta al modelo Llama 3]
     ↓
[Llama 3 genera respuesta basada en contexto]
     ↓
[Respuesta precisa y contextualizada]

VENTAJAS:
✓ Respuestas basadas en tus documentos
✓ 100% local (sin API externa)
✓ Datos privados (en tu PC)
✓ Rápido y preciso

⚙️ PERSONALIZACION
================================================================================

Si quieres ajustar el sistema, edita config.json:

1. Tamaño de fragmentos (chunk_size):
   - Por defecto: 500 palabras
   - Aumentar para papers largos (600-1000)
   - Disminuir para búsqueda rápida (300-400)

2. Cantidad de documentos recuperados (retrieval_k):
   - Por defecto: 3
   - Aumentar para más contexto (5-10)

3. Modelo de embeddings:
   - all-MiniLM-L6-v2 (por defecto, rápido, 90MB)
   - all-mpnet-base-v2 (más preciso, 420MB)
   - multilingual-e5-base (multiidioma, 200MB)

4. Creatividad del modelo (temperature):
   - 0 = Respuestas precisas y consistentes
   - 1 = Respuestas creativas y variadas
   - Recomendado: 0.5-0.8


❓ PREGUNTAS FRECUENTES
================================================================================

P: ¿Necesito internet?
R: Solo para descargar los modelos la primera vez. Luego funciona offline.

P: ¿Cuánta memoria necesito?
R: ~2GB para Llama 3 + ~200MB para embeddings + ~50MB por 1000 chunks

P: ¿El sistema es privado?
R: Sí, todo corre localmente. Ningún dato se envía a servidores externos.

P: ¿Cómo mejoro la precisión?
R: Aumenta retrieval_k, usa all-mpnet-base-v2, proporciona PDFs de calidad

P: ¿Funciona con otros formatos?
R: Actualmente solo PDFs. Puedes extender el código fácilmente.
